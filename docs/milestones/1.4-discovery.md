# Milestone 1.4 - public browsing and discovery

## Gate and outcome

Requires accepted 1.3, then separate planning and BUILD approval for 1.4. Replace the foundation preview with real public discovery from approved local data, while keeping unavailable communication controls honest until 1.5. No public launch yet.

## Plan

Inspect actual schema, listing/media visibility and routes. Plan the query/index strategy, API field projections, public caching and invalidation, URL filter model, responsive pages, favourites ownership, metadata, error states, and migration impact. Native artifact and `docs/plans/1.4-plan.md` must agree.

## Build batches

A. Bounded search: PostgreSQL full-text search with category, city/locality, price and condition filters; relevance/newest/price ordering with stable tie-breakers; bounded pagination and validated URL parameters. Document language limitations. Do not pretend city selection is accurate distance search.

B. Public screens: homepage with real available listings, categories, search results, listing details keyed by stable ID/slug, minimal seller profiles and other available listings. Add responsive listing cards, photo galleries and usable empty/error/loading states. Old slugs redirect only after visibility is checked.

C. Favourites: authenticated per-user save/remove/list with correct behavior for no-longer-public advertisements. Hidden items must not leak titles/photos through favourite joins to unauthorized viewers.

D. Metadata/visibility: server-render permitted pages; accurate canonical URLs and social metadata; bounded sitemap/indexable category/location pages; no endless filter permutations; no private/draft data in HTML, API payloads, caches, structured data or image paths. Keep internal development environment non-indexed.

E. Help/policy draft pages: publish truthful project guidance with draft labels and no invented legal identity. Contact/report actions must not claim operational handling until 1.5; omit or explain unavailable controls. Do not create dead links or false notifications.

## Tests

Combined filter/sort/pagination correctness including identical prices/timestamps, invalid query inputs, zero-result searches, unavailable listing direct routes, obsolete slugs, minimal seller fields, favourite cross-user access, approved-content edit/removal and cache behavior, hidden images, and public metadata leakage.

Run desktop/mobile browser journeys for finding a moderator-approved listing and favouriting it with actual authentication. Check keyboard filter controls, gallery behavior and responsive overflow. Use performance measurements under stated conditions; no invented Lighthouse/search ranking scores.

## Exclusions

No external search engine, recommendations, saved-search alerts, structured offers, chat, paid placements, maps/distance precision, or newly opened launch markets without authorization.

## Acceptance

- Real approved listings are discoverable with correct combined filters and stable pagination.
- Listing and seller pages reveal only authorized public fields/media.
- Favourites persist securely; non-public content is withheld everywhere.
- Responsive states, metadata, draft policy content and planned contacts are honest.
- Actual query/RLS/browser tests, cache checks and earlier regressions pass.
- Search design, limitations, indexes and evidence documented; stop for review before 1.5.
