# Milestone 1.6 - release hardening and controlled-pilot readiness

## Gate and outcome

Requires accepted 1.5, then separate planning and BUILD/verification authorization for 1.6. Deliver an evidence-based go/no-go assessment of the implemented Phase 1, fix in-scope defects, and prepare a controlled pilot. This milestone never grants automatic public deployment or access to production data.

## Plan

Inspect actual feature completion rather than trusting checkboxes. Propose regression, authorization, recovery, performance, accessibility, browser coverage, and operational checks with an explicit local/staging target. Document any environment or privileged action needing separate permission. Prioritize completing required Phase 1 controls over new features.

Define target-browser support with the owner. Keep Chromium baseline, but assess additional browser/device checks according to launch claims; add required engines only after reviewed installation scope. Responsive emulation is not real-device validation. Unverified support remains a limitation.

## Work batches

A. End-to-end acceptance: test registration/confirmation/recovery, listing submission/photos, staff review, discovery/favourites, two-session messaging, blocking/reporting/support, sold/expired states, privacy processing, and role-restricted staff actions.

B. Security and privacy: review schema/grants/functions/RLS/storage/Realtime, cookie/session handling, stale restrictions, object ownership, protected columns, MFA, input size/rate limits, redirects/XSS, cached private data, media URLs, reporter privacy, staff evidence and audit. Review dependencies/configuration. Do not represent agent testing as an independent professional security audit.

C. Reliability: simulate interrupted upload, failed processing/email, unavailable live connection, duplicate event/job handling, expired session, job retries and cleanup. Verify bounded query/index behavior and a modest measured load smoke test on an authorized target. Never load-test external systems without permission.

D. Recovery and operations: document database AND image-byte backups, actual restoration into an isolated permitted environment, recovery checks, maintenance authentication, notification failures, escalation, monitoring/usage alerts, rollback and incident procedures. Separate a written procedure from an executed restore. No production reset, secret exposure or destructive testing.

E. User experience: real desktop/mobile inspection, keyboard flows, contrast/labels, empty/loading/error states and honest policies. Verify removed-content behavior in pages, metadata and media. Capture and inspect evidence; record limitations instead of invented quality scores.

F. Release documentation: create final schema/permissions/security/setup/testing/deployment/operations/launch-checklist documents that describe implemented behavior. Prepare hosted Next.js/Supabase deployment steps, redirect configuration, storage/Realtime/jobs, secrets, environment separation, monitoring, owner contacts and manual approvals. Do not provision or deploy unless separately authorized.

## Go/no-go evidence

Record required checks, actual results, open defects by severity, browser/device coverage, performance conditions, restoration evidence, and operational ownership. Separate:

1. Code implemented and verified.
2. Implemented but not verified or not configured.
3. External blockers: domain ownership, production email/provider setup, business identity/contact/grievance details, privacy/legal review, moderation/support staffing, monitoring/backup configuration.
4. Features deferred by product scope.

Do not mark production-ready when required checks or business prerequisites are missing. A local release candidate can be code-ready while public launch remains blocked. Any pilot launch requires a separate explicit user decision and deployment authorization.

## Acceptance

- All required Phase 1 user/staff journeys and security regressions pass on stated targets.
- No unresolved critical authorization/privacy/data-loss defect is hidden.
- Recovery, failure handling, mobile/desktop and agreed browser checks have real evidence or explicit blockers.
- Runbooks, environment configuration and setup are reproducible and truthful.
- Support/moderation responsibilities and legal/provider launch gaps are listed.
- Human receives a documented go/no-go recommendation and exact remaining actions.

Stop for review. Do not begin Phase 2, deploy automatically, send real-user emails, change DNS or charge anyone.
