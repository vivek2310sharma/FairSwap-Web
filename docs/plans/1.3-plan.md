## 2. Goal & Product Boundary

Deliver the seller-to-moderator listing lifecycle on local Supabase: configurable categories with typed attributes, location hierarchy, listing CRUD with structured validation, safe photo upload/processing pipeline, staff moderation queue, and enforced state transitions — locally testable without external services.

### 2.1. In Scope

- **Category/attribute administration**: Configurable categories with typed attribute definitions (required/optional, filterable); staff management screens; deterministic pilot seed data in migration.
- **Location hierarchy**: City/locality reference data; approximate location on listings; optional PIN code.
- **Listing CRUD & lifecycle**: Draft → pending_review → active → reserved → sold, plus rejected, paused, expired, removed. Owner-managed dashboard, bounded validation, integer paise pricing.
- **Strict material-edit re-review**: Any seller change to material fields or photos while in `active`, `reserved`, or `paused` transitions the listing to `pending_review` and increments revision. Editing a `rejected` listing transitions it to `draft`.
- **Photo pipeline**: Real Supabase Storage with private-only buckets; server-mediated uploads, access, and deletion; content-type validation, safe decode with explicit pixel bounds, auto-orient, EXIF strip, re-encode, derivative generation, cover/order management, per-file status tracking, orphan tracking.
- **Staff moderation**: Pending queue, approve/reject/remove with reasons, audit all moderation actions.
- **Database enforcement**: State transition matrix in SQL triggers/checks; RLS and explicit column-level GRANTs for all new tables; trusted vs user-editable field separation via column-level INSERT/UPDATE grants; direct `listing_media` DELETE revoked from authenticated.
- **Maintenance jobs**: Idempotent expiry check and orphan media cleanup (stale uploading/processing/failed, partial derivatives, orphan storage objects) via Storage API.
- **Seed data**: ~30 clearly synthetic listings with licensed/local image fixtures via dev-only script (NOT a migration); fail-closed localhost-only safety check.
- **Observability**: Listing-domain audit events; operational logging for listing/media/moderation flows.
- **Public-read authorization function**: Reusable `app_security.is_listing_publicly_visible()` helper for future 1.4 discovery; anonymous SELECT on `listings` revoked for 1.3.
- **Documentation synchronization**: README.md, PROGRESS.md, and other project docs updated to reflect verified Milestone 1.3 implementation.

### 2.2. Explicitly Excluded

- Public discovery pages, search, filtering, and pagination (Milestone 1.4).
- Public/anonymous media delivery, public Storage bucket, `next/image` optimization for listing photos (Milestone 1.4).
- Favourites (Milestone 1.4).
- Messaging and Realtime (Milestone 1.5).
- Reports, support cases, and appeals (Milestone 1.5/1.6).
- Automated privacy-request fulfillment for listing data (Milestone 1.5).
- Subscriptions, paid promotion, billing, or purchase flows.
- Public star ratings or seller guarantees.
- External search clusters, CDN configuration, or production deployment.
- Native apps, AI moderation, or automated keyword heuristics (manual review only for pilot).

## 4. Database / Schema Architecture

### 4.1. Enums
- `listing_status_enum`: `'draft'`, `'pending_review'`, `'active'`, `'reserved'`, `'sold'`, `'rejected'`, `'paused'`, `'expired'`, `'removed'`
- `listing_condition_enum`: `'new'`, `'like_new'`, `'good'`, `'fair'`, `'poor'`
- `listing_price_type_enum`: `'fixed'`, `'negotiable'`, `'free'`
- `attribute_value_type_enum`: `'text'`, `'number'`, `'select'`, `'boolean'`
- `media_processing_status_enum`: `'uploading'`, `'processing'`, `'ready'`, `'failed'`
- `transition_actor_kind_enum`: `'seller'`, `'moderator'`, `'system'`

### 4.2. Consistency Constraints on `listing_status_transitions`
- `actor_kind = 'system'` <=> `actor_id IS NULL`
- `actor_kind IN ('seller', 'moderator')` <=> `actor_id IS NOT NULL`
- When `to_status IN ('rejected', 'removed')`, `reason IS NOT NULL AND length(trim(reason)) > 0`

### 4.3. Material-Edit Trigger Logic
- Triggers on `listings` (`BEFORE UPDATE`) and `listing_media` (`AFTER INSERT`, `AFTER DELETE`, `AFTER UPDATE` of `display_order`):
  - If parent listing `status IN ('active', 'reserved', 'paused')`:
    - Material fields modified (`title`, `description`, `category_id`, `condition`, `price_type`, `price_paise`, `cover_photo_id`, or media added/deleted/reordered):
      - Transition `status` to `'pending_review'`
      - Increment `revision`
      - Record transition in `listing_status_transitions`
  - If parent listing `status = 'rejected'`:
    - Seller allowed content update transitions `status` to `'draft'`
    - Increment `revision`
    - Clear current trusted `rejection_reason` on `listings` row
    - Historical rejection reason preserved in `listing_status_transitions` and audit logs
- Paused listings that are materially edited become `pending_review`; `seller_transition_listing('resume')` requires current status `'paused'` and prior approval record without pending revisions.

### 4.4. Column Grants & RLS Matrix

#### `public.listings`
- `anon`: No SELECT, INSERT, UPDATE, DELETE (revoked for 1.3; discovery in 1.4).
- `authenticated`:
  - `SELECT`: Own listings (`seller_id = auth.uid()`).
  - `INSERT` (column-level): `category_id`, `city_id`, `locality_id`, `title`, `description`, `condition`, `price_type`, `price_paise`, `pin_code`, `category_attributes`. (`cover_photo_id` excluded).
  - `UPDATE` (column-level): Same as INSERT + `cover_photo_id`.
  - `DELETE`: Denied (use status transitions).
- Staff (moderator+, AAL2): SELECT all.

#### `public.listing_media`
- `anon`: No grants.
- `authenticated`:
  - `SELECT`: Own listing's media.
  - `INSERT` (column-level): `listing_id`, `original_filename`, `content_type`, `file_size_bytes`.
  - `UPDATE`: `display_order` only.
  - `DELETE`: **REVOKED/DENIED**. Media deletion is mediated via `DELETE /api/listings/[id]/media/[mediaId]`.
- Staff: SELECT all for moderation.

## 5. Storage Architecture (Service-Mediated)

- Buckets: `listing-originals` (private), `listing-derivatives` (private).
- No `anon` or `authenticated` Storage policies. All operations server-mediated via server service-role client.
- Signed URLs issued only to authenticated owner or staff with moderator role + AAL2. No anonymous signed URLs in 1.3.

## 6. Route Handlers & Server Pipeline

### 6.1. Photo Upload: `POST /api/listings/[id]/media`
1. Early auth: authenticate caller & verify listing ownership / active status BEFORE calling `request.formData()`.
2. Content-Length check: reject if > 6 MB.
3. Call `request.formData()`; require exactly one `File`; check `File.size <= 5 MB`.
4. Slice initial 12 bytes to inspect magic bytes (JPEG/PNG/WebP). Reject SVG/other formats.
5. Authenticated SSR client INSERTs `listing_media` row (`uploader_id = auth.uid()`, `processing_status = 'uploading'`).
6. Service-role client uploads original to `listing-originals/{listing_id}/{media_id}/original.{ext}`.
7. Service-role calls `public.record_media_processing_result` -> status `processing`.
8. Sharp processes image with `limitInputPixels = 64_000_000`, auto-orient, metadata inspection, format verification, dimensions check (<= 8000x8000), generates thumb, medium, large WebP.
9. Service-role client uploads derivatives to `listing-derivatives`.
10. Service-role calls `public.record_media_processing_result` with paths, dimensions, status `ready`.
11. On any failure: service-role records status `failed` with error message.

### 6.2. Photo Deletion: `DELETE /api/listings/[id]/media/[mediaId]`
1. Authenticate caller and verify listing ownership.
2. Retrieve trusted Storage paths from DB.
3. If this media is `cover_photo_id`, safely clear/reassign cover photo on the listing.
4. Delete original + derivative objects from Supabase Storage via Storage API.
5. Perform DB deletion via server-controlled service-role mechanism.
6. Trigger material-edit re-review behavior if listing is `active`, `reserved`, or `paused` (transitions to `pending_review`, increments revision).
7. Log audit event.

### 6.3. Media Access: `GET /api/listings/[id]/media/[mediaId]/[size]`
1. Requires authentication.
2. Caller must be listing owner or staff with moderator + AAL2.
3. Returns short-lived signed URL (302 redirect) with `Cache-Control: private, no-store`.
