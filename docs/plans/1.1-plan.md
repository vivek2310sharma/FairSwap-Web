### Prerequisite: install pnpm

pnpm is not installed. Installation involves three distinct actions:

1. **Global shim activation** — `corepack enable pnpm` modifies the global Node.js `bin/` directory to create a `pnpm` command shim. This is a machine-level change to the PATH-accessible commands. It does not download pnpm itself yet. Requires explicit approval as a global shim change.

2. **Package-manager binary download** — When `pnpm` is first invoked (or when `packageManager` is set in `package.json`), corepack downloads the specified pnpm version from the npm registry into a local corepack cache (`%LOCALAPPDATA%\node\corepack`). This is a network download, not merely enabling a built-in binary.

3. **Project dependency installation** — `pnpm install` at the workspace root downloads project dependencies into `node_modules/` and creates `pnpm-lock.yaml`. This is separate from steps 1–2.

**Planned sequence** (during BUILD, not planning):

```powershell
# Step 1: Activate the pnpm shim (global change — requires approval)
corepack enable pnpm
```

Do NOT run `corepack use pnpm@latest` in the populated root before `package.json` exists. Instead:
- Generate the scaffold in the temp directory (step uses npx, which is already available)
- Transfer `package.json` to the root and set `name` to `"fairswap"`
- Pin an exact compatible pnpm version in the `packageManager` field of the root `package.json`
- Then run `pnpm install` at the root (corepack downloads the pinned pnpm version on first invocation)

**If `corepack enable` requires elevation or fails** due to PowerShell security policy: stop, report the exact error, and propose a specific alternative with separate approval. Do not automatically fall back to `npm install -g pnpm` or relax execution policy.

## Playwright: browser binary vs OS dependencies

- **Chromium binary download** (`pnpm exec playwright install chromium`): downloads a self-contained Chromium into a local cache directory (typically `%LOCALAPPDATA%\ms-playwright`). This is a project-level download, not a system install. Requires BUILD approval + terminal review.

- **OS system dependencies** (`playwright install-deps chromium`): installs Windows system libraries needed to run headless Chromium. On Windows 11, Chromium typically runs without additional OS dependencies. If tests fail due to missing system libraries, the exact required command will be proposed separately with explanation. This is a **separate approval category**.

- No Firefox or WebKit downloads in 1.1.
- Viewport tests are NOT real-device or cross-browser coverage claims.

## Process management

During BUILD, servers are started and stopped deliberately:

- `pnpm dev` in Batch 1: started to verify scaffold, stopped before proceeding.
- `pnpm start` in Batch 6 manual verification: started on a specific port, verified, stopped.
- Playwright `webServer` in Batch 5/6: configured to start `pnpm start` on a test-owned port (e.g., 3001), with Playwright managing the lifecycle (start before tests, stop after).

Only processes started for this task are stopped. No background server is left running between batches that could cause port conflicts or stale-process test contamination.

## Recovery procedure

If scaffold transfer or later implementation causes problems at the workspace root:

1. **Inspect** the current state of changed files. Use `git status` and `git diff` to identify exactly what was modified, added, or deleted.
2. **List the affected paths** explicitly. Distinguish instruction-pack files (must be preserved), newly created application files, and any unexpected changes.
3. **Do not** run blanket `git checkout -- .` or `git clean -fd`. These commands would discard all uncommitted work indiscriminately, including any application code already built in earlier batches.
4. **Propose specific recovery actions** for each affected path:
   - Instruction-pack files accidentally modified → restore individually with `git checkout -- <path>`
   - Failed application files → remove specific identified paths
   - Partially transferred scaffold → report which files were and were not transferred
5. **Request explicit approval** before restoring or deleting any files. State what each action will do and what it will affect.
6. **Do not** create commits, push changes, or perform whole-project resets as an automatic fallback.
7. If the temp scaffold directory still exists, it serves as a reference for the original generated state.
